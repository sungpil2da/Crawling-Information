# 인스타그램 자동 응답

내 게시물에 댓글이 달리거나 DM이 오면, 키워드를 보고 정해둔 내용을 DM으로 보냅니다.
Meta 공식 API만 사용하고, 브라우저 자동화나 스크래핑은 쓰지 않습니다.

```
누군가 댓글 "자료"  ─┐
                     ├─→  웹훅  →  키워드 확인  →  DM 발송  →  기록
누군가 DM "가격?"   ─┘
```

---

## 먼저 알아둘 제약

이건 코드로 우회할 수 없는 Meta의 규칙입니다. 설계할 때 여기에 맞춰야 합니다.

| | 댓글 → DM | 받은 DM → 답장 |
|---|---|---|
| 보낼 수 있는 기간 | 댓글 작성 후 **7일** | 상대 마지막 메시지 후 **24시간** |
| 횟수 | 댓글당 **정확히 1회** | 창 안에서는 제한 없음 |
| 발송 상한 | 시간당 750건 | 계정별 속도 제한 적용 |
| 라이브 방송 댓글 | 방송 중에만 | — |

7일은 웹훅을 받은 시각이 아니라 **댓글이 달린 시각**부터 셉니다.

먼저 연락한 적 없는 사람에게 보내는 콜드 DM은 공식 API로 불가능합니다. 이 프로젝트도 하지 않습니다.

---

## 1. 계정과 Meta 앱 준비

**인스타그램 계정을 프로페셔널(비즈니스 또는 크리에이터)로 전환**합니다. 개인 계정은 API를 쓸 수 없습니다.

[developers.facebook.com](https://developers.facebook.com)에서:

1. 앱 만들기 → 유형 **비즈니스** 선택
2. 제품 추가 → **Instagram** → *API setup with Instagram login* 선택
   (이 방식은 페이스북 페이지 연결이 필요 없습니다)
3. 인스타그램 계정 연결 후 다음 권한을 요청:
   - `instagram_business_basic`
   - `instagram_business_manage_messages`
   - `instagram_business_manage_comments`
4. **앱 시크릿**과 **인스타그램 계정 ID**, **장기 액세스 토큰**을 복사해 둡니다

> **검수 없이 쓸 수 있나?**
> 본인 계정 하나만 자동화한다면 개발 모드로 충분합니다. 앱에 테스터로 등록된 계정에는 검수 없이 동작합니다.
> 남의 계정을 연결하는 서비스로 만들 거라면 App Review가 필요하고, 메시지 권한은 심사가 오래 걸리는 편입니다.

## 2. 로컬 실행

```bash
npm install
cp .env.example .env      # 값 채우기
npx netlify dev
```

`ADMIN_TOKEN`은 직접 만드세요:

```bash
openssl rand -hex 24
```

---

## 3. 배포

```bash
npx netlify deploy --prod
```

Netlify 대시보드 → **Site configuration → Environment variables**에 `.env`의 값을 그대로 넣습니다.
로컬 `.env` 파일은 배포되지 않으므로 이 단계를 건너뛰면 함수가 뜨자마자 죽습니다.

---

## 4. 웹훅 연결

Meta 앱 콘솔 → **Instagram → Webhooks**:

| 항목 | 값 |
|---|---|
| Callback URL | `https://내-사이트.netlify.app/webhook` |
| Verify Token | `.env`의 `IG_VERIFY_TOKEN`과 **똑같이** |

구독할 필드: **`comments`**, **`messages`**

"Verify and Save"를 누르면 Meta가 GET 요청을 보내 확인합니다.
실패하면 배포가 끝났는지, Verify Token 양쪽이 일치하는지 확인하세요.

마지막으로 인스타그램 앱에서 **설정 → 메시지 → 연결된 도구**에 들어가 메시지 접근을 허용합니다.
이걸 빼먹으면 댓글 웹훅은 오는데 DM만 계속 실패합니다.

---

## 5. 규칙 설정

`https://내-사이트.netlify.app/` 에 접속해 `ADMIN_TOKEN`으로 열면 됩니다.

- 규칙은 **위에서부터** 검사하고 처음 맞는 하나만 실행합니다. 좁은 조건을 위에 두세요.
- 키워드는 쉼표로 구분합니다. 대소문자·공백·문장부호·이모지는 무시하고 비교합니다.
- 저장하면 즉시 반영됩니다. 재배포할 필요 없습니다.

---

## 동작 확인

다른 계정으로 내 게시물에 등록한 키워드를 댓글로 답니다. 몇 초 안에 DM이 와야 합니다.

안 오면 **최근 발송** 목록을 먼저 보세요. 여기가 비어 있으면 웹훅이 아예 안 들어온 것이고,
`실패`로 찍혔으면 발송 단계 문제입니다. 자세한 원인은 Netlify → Functions → `webhook` 로그에 있습니다.

---

## 자주 나오는 실패

| 증상 | 원인 |
|---|---|
| `code 10` | 24시간 창이 닫혔습니다. 상대가 다시 메시지를 보내야 합니다 |
| `code 100` / subcode 2534025 | 댓글이 7일을 넘었거나, 이미 답장했거나, 상대가 메시지 요청을 막아뒀습니다 |
| `code 190` | 토큰 만료. 계정을 다시 연결해야 합니다 |
| `code 368` | 너무 빨리 보내 계정이 일시 정지됐습니다. 24~48시간 멈추고 속도를 낮추세요 |
| `code 508` | 이 계정은 링크 공유가 제한돼 있습니다. 메시지에서 URL을 빼보세요 |
| 401 Invalid signature | `IG_APP_SECRET`이 틀렸습니다 |

## 구조

```
netlify/functions/
  webhook.js        댓글·DM 이벤트 수신 → 규칙 판정 → 발송
  admin.js          관리 화면용 API (ADMIN_TOKEN 필요)
  refresh-token.js  매주 월요일 토큰 자동 갱신
lib/
  ig.js             Graph API 호출과 에러 해석
  match.js          서명 검증, 키워드 정규화·매칭, 7일 창 계산
  store.js          Netlify Blobs — 규칙·중복방지·토큰·기록
public/index.html   관리 화면
test/
  match.test.mjs    키워드 매칭·서명 검증·7일 창 계산 (19개)
  webhook.test.mjs  가짜 Graph API를 물린 웹훅 전 구간 (22개)
```

배포하기 전에 한 번 돌려보세요. 실제 API를 부르지 않고 41개 항목을 확인합니다.

```bash
npm install
npm test
```

**설계상 신경 쓴 부분**

- 웹훅은 어떤 예외가 나도 200을 돌려줍니다. 아니면 Meta가 같은 이벤트를 계속 재시도합니다.
- `X-Hub-Signature-256`을 검증합니다. 안 하면 URL을 아는 누구나 가짜 이벤트로 DM을 쏘게 만들 수 있습니다.
- 발송 전에 `comment_id` / `mid`를 선점해 재시도로 인한 이중 발송을 막습니다.
  단, 네트워크 오류처럼 Meta가 거절한 게 아닌 경우엔 선점을 풀어 재시도가 통하게 합니다.
- `is_echo` 메시지를 걸러냅니다. 내가 보낸 DM이 되돌아오는데, 여기 반응하면 자기 자신과 무한 대화를 합니다.
- 시간당 발송량을 세서 Meta 상한(750건)에 닿기 전에 멈춥니다. 기본값은 여유를 둔 700건이고 `IG_HOURLY_CAP`으로 조정합니다.
  게시물이 터졌을 때 이 장치가 없으면 code 368로 계정이 하루 이틀 묶입니다. 한도로 건너뛴 댓글은 기록에 사유가 남습니다.
- 장기 토큰은 60일마다 만료됩니다. 주간 스케줄로 갱신해 조용히 멈추는 일을 막습니다.

## 확장 여지

- **LLM 응답**: `deliver()` 앞에 문의 분류를 붙이면 고정 문구 대신 맥락에 맞는 답을 보낼 수 있습니다. 다만 24시간 창 안에 들어와야 하니 응답 지연에 상한을 두세요.
- **스토리 답장·멘션**: 웹훅 필드에 `messaging_postbacks`, `mentions`를 추가하면 같은 구조로 확장됩니다.
- **사람에게 넘기기**: 규칙에 안 걸리는 문의는 알림만 보내고 자동 응답을 끄는 편이 대체로 낫습니다.
